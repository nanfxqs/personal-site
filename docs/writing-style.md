# Writing Style Guide (知识点正文写作风格规范)

本规范由作者在逐节拍（Beat-by-beat）审校中沉淀而成，用于指导站点知识点正文的语言调性、叙事节奏与排版细节。随着审校推进持续迭代。

## 1. 语言调性：现代技术教材感
- **严谨克制、零情绪铺垫**：参考 *CSAPP*、*Hello 算法* 等高赞开源教材风格，禁止使用“刚学时最容易劝退”、“突然冒出”、“死循环”等松散口语或闲聊感叹。
- **高信息密度、去冗余**：每句话都必须承担定义、因果推演或机制解释功能，不堆砌“首先/其次/综上所述”等空洞过渡。
- **同类概念句式对齐**：同一组并行定义保持结构对称（如 `X（锁存器）保持被乘数或除数不变，ACC（累加器）存放部分积或中间余数，MQ（乘商寄存器）存放乘数或商`）。

## 2. 叙事节奏与概念锚定（Grounding）
- **先立规矩，后消化**：开篇先简洁、准确地建立运算框架与静态定义，不在开篇过早剧透动态拼接细节，留待后续推导中自然消化。
- **顺承读者预期，禁止生硬贴标签**：不要在段首突然抛出“类比 XX：”等刻意句式；应顺着前一句留下的问题继续推导，在需要直观佐证时再自然引出类比。
- **标题不剧透、推导不抢跑**：小节标题保持客观命名（如 `### 1. 原码加减交替除法`），避免预设读者已懂结论的反问式标题；讲解优化算法前，先用独立节拍把朴素方法讲透，再顺理成章推出简化公式。
- **先讲“为什么这样设计”，再落到规则**：通过代数恒等式或硬件约束解释算法背后的本质（如“为何右移部分积”、“为何折叠连续 1 串”、“为何负余数直接 ×2 加除数”），避免把知识写成死记硬背的口诀表。

## 3. 注意力边界与交叉引用
- **正文核心链路零打断**：在开篇定调与关键推导句中，**禁止**插入打断阅读心流的括号外链（如 `(并行实现见 <TopicLink ... />)`）。
- **只在逻辑必然处自然引入关联**：不在文末强行堆砌“跨知识点衔接”汇总段落；只有当当前推演自然触及延伸边界时（如串行优化到极限后自然引入并行阵列），才在叙事中顺势带出 `<TopicLink />`。

## 4. 可视化与 Markdown 排版
- **直观过程配 2D 可视化**：涉及位对齐、移位步进或资源开销对比时，优先配合 2D 交互图示呈现“计算过程 → 产生结果/痛点”。
- **图文穿插，按节拍就地消化**：每个核心算法推导完成后，紧接着穿插该算法对应的 2D 交互演示，并在图下方用简短收束句点明寄存器状态与复杂度，避免把多个算法的演示集中堆砌在后半段。
- **演化主线用流程图收束**：多算法并列的篇幅收尾时，用可视化流程图串联“痛点 → 优化手段 → 时钟周期收益”的演进脉络，代替纯文字罗列。
- **Markdown 边界安全**：加粗 `**` 不得直接贴合汉字与中文引号外侧（应置于引号内，如 `“**1 次加减**”`）；GFM 表格单元格内的绝对值竖线使用 `\lvert ... \rvert`，避免与表格分列符冲突。
